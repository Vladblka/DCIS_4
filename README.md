# Практическая работа №6: веб-приложение «Учёт музыкальных инструментов»

Веб-приложение на Spring Boot для хранения сведений о музыкальных инструментах.
Вариант: «Музыкальный инструмент».

В работе №6 добавлены регистрация, вход, роли User/Admin и разграничение доступа
к страницам. Пароли хранятся в PostgreSQL в виде BCrypt-хешей.

## Цель работы

Освоить разработку веб-приложения на Spring Boot: обработку HTTP-запросов
контроллерами, формирование HTML-страниц, проверку введённых пользователем данных,
выполнение CRUD-операций через `JdbcTemplate` и настройку безопасности
средствами Spring Security.

## Пользователи и роли

| Пользователь | Логин | Пароль | Роль | Как создаётся |
|---|---|---|---|---|
| Администратор | `admin` | `admin` | `ADMIN` | автоматически при первом запуске (`AdminInitializer`) |
| Пользователь | любой | любой | `USER` | через страницу регистрации |

Информация хранится в таблице `app_users`:

```sql
CREATE TABLE IF NOT EXISTS app_users (
    id BIGSERIAL PRIMARY KEY,
    username VARCHAR(60) NOT NULL UNIQUE,
    password VARCHAR(100) NOT NULL,
    role VARCHAR(20) NOT NULL CHECK (role IN ('USER', 'ADMIN'))
);
```

Пароль не хранится открытым текстом: `UserService.register()` кодирует его
`BCryptPasswordEncoder`, в базе лежит хеш. При входе Spring Security сравнивает
введённый пароль с хешем.

## Безопасность

Правила описаны в `SecurityConfig`:

```java
.requestMatchers("/login", "/register", "/css/**", "/error").permitAll()
.requestMatchers(HttpMethod.GET, "/instruments", "/instruments/search")
        .hasAnyRole("USER", "ADMIN")
.requestMatchers("/instruments/**").hasRole("ADMIN")
.anyRequest().authenticated()
```

- Форма входа **своя**, а не сгенерированная Spring: `loginPage("/login")`
  указывает на шаблон `login.html`, поле `formLogin` обрабатывает POST `/login`.
- Выход: POST `/logout`, после него редирект на `/login?logout`.
- CSRF-защита включена; Thymeleaf сам добавляет скрытое поле `_csrf`
  во все формы с `th:action`.
- `UserService` реализует `UserDetailsService`, поэтому Spring Security
  загружает пользователя из `app_users` и проверяет BCrypt-хеш.

### Безопасность на уровне представлений

В шапке (`fragments/common.html`) и на главной используются атрибуты
`sec:authorize` и `sec:authentication` из `thymeleaf-extras-springsecurity6`:

- после входа выводится «Привет, `<логин>`»;
- рядом с именем показывается бейдж роли «Администратор» или «Пользователь»;
- ссылки «Добавить», «Изменить», «Удалить» и карточки этих разделов видны
  только при `hasRole('ADMIN')`;
- кнопка «Выйти» показывается только авторизованному пользователю;
- гостю показываются кнопки «Войти» и «Регистрация».

## Проверка вводимых данных

Проверки выполняются на сервере; при ошибке форма показывается снова,
введённые значения сохраняются, под полем выводится сообщение.

| № | Что проверяется | Сообщение |
|---|---|---|
| 1 | Текстовые поля инструмента не пустые | «Укажите название инструмента», «Укажите бренд» и т.д. |
| 2 | Длина текста не больше размера колонки БД | «Название не должно быть длиннее 120 символов» |
| 3 | Цена — число и не отрицательная | «Цена должна быть числом, например 85000.50», «Цена не может быть отрицательной» |
| 4 | У цены не более 10 цифр до запятой и 2 после | «Цена: не более 10 цифр до запятой и 2 после» |
| 5 | Количество — целое и не отрицательное | «Количество должно быть целым числом, например 3», «Количество не может быть отрицательным» |
| 6 | Логин: 3–60 символов, латиница, цифры, `_` | «Логин должен содержать от 3 до 60 символов», «Логин может содержать только латинские буквы, цифры и _» |
| 7 | Пароль: 4–60 символов | «Пароль должен содержать от 4 до 60 символов» |
| 8 | Пароли совпадают | «Пароли не совпадают» |
| 9 | Логин ещё не занят | «Пользователь с таким логином уже существует» |
| 10 | Поисковый запрос не пустой | «Введите часть названия бренда для поиска» |

Проверки полей инструмента и формы регистрации описаны аннотациями
`@NotBlank`, `@Size`, `@NotNull`, `@DecimalMin`, `@Digits`, `@Min`, `@Pattern`.
Совпадение паролей и уникальность логина проверяются в `AuthController`.
Ошибки преобразования чисел выводятся из `messages.properties`.

## Описание конфигурации

Spring Boot создаёт `DataSource` и `JdbcTemplate` по параметрам из
`application.properties`, а также бины Spring Security. Дополнительно объявлены:

- `SecurityConfig` — цепочка фильтров, правила доступа, вход и выход;
- `PasswordEncoder` — `BCryptPasswordEncoder`;
- `UserService` — `UserDetailsService` + регистрация пользователей;
- `AdminInitializer` — создаёт `admin/admin` при первом запуске.

Параметры подключения:

```properties
server.port=${SERVER_PORT:8080}

spring.datasource.url=${DB_URL:jdbc:postgresql://localhost:5432/music_store}
spring.datasource.username=${DB_USER:postgres}
spring.datasource.password=${DB_PASSWORD:postgres}
```

`schema.sql` выполняется при каждом запуске, таблицы создаются через
`CREATE TABLE IF NOT EXISTS`, существующие данные не теряются.

## Как запустить

1. Создать базу данных (если ещё не создана):

   ```sql
   CREATE DATABASE music_store;
   ```

2. Запустить приложение:

   ```bash
   mvn spring-boot:run
   ```

3. Открыть <http://localhost:8080>. Откроется страница входа.
4. Войти как администратор: `admin` / `admin` — или зарегистрировать нового
   пользователя и войти под ним.

Требования: Java 17+, Maven, PostgreSQL.

## Как пользоваться

1. **Регистрация** — задать логин и пароль, повторить пароль. Новому
   пользователю присваивается роль `USER`.
2. **Вход** — ввести логин и пароль на странице `/login`.
3. **USER** видит таблицу записей и поиск; кнопок изменения и удаления нет.
4. **ADMIN** дополнительно добавляет, изменяет и удаляет записи.
5. **Выход** — кнопка «Выйти» в шапке, после неё открывается страница входа
   с сообщением «Вы вышли из системы».

После успешных операций над таблицей выводится сообщение, например
«Запись №1 добавлена.». Если запись с указанным id не найдена, открывается
страница ошибки 404 с текстом «Запись №… не найдена».
